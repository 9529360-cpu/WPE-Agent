# Token 消耗分析

## 历史异常原因

最可能的高消耗来源是旧版本把远程 Planner 放在交易循环中。每个周期都会提交市场证据、多个品种评估、新闻正文摘要、持仓、账户和近期结果。由于旧版本没有调用审计，无法从本地数据精确重建供应商账单中的 Token 数量和费用。

历史日志中的 DeepSeek HTTP 402 与一天内额度快速耗尽相互吻合，但只能证明余额不足，不能单独证明具体 Token 数。

## 当前状态

- 交易运行时：`WPE Local Brain`，远程调用次数为 0。
- 策略研究：本地计算，远程调用次数为 0。
- 新闻采集：RSS/网页数据请求，不消耗 LLM Token。
- 远程模型：仅在用户主动测试或未来显式辅助任务中调用。

## 新审计数据

新版本从首次远程调用开始写入：

`%LOCALAPPDATA%/WPE Agent/Data/llm-calls.jsonl`

每行包含：时间、Provider、Model、调用目的、Prompt 哈希、缓存命中、是否允许、估算输入/输出 Token、估算费用、耗时和结果。

费用是保守估算，不替代供应商账单；后续 Adapter 应优先读取供应商返回的实际 usage 字段。

## 默认预算

- 100 次/UTC 日
- 250,000 估算 Token/UTC 日
- 10 USD 估算费用/UTC 日
- 15 分钟相同 Prompt 缓存

任何预算达到上限后，远程辅助层停止调用，但本地交易、风控、策略研究和数据采集继续运行。
