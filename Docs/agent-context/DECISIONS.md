# Decisions

- WPF remains the authority for secrets and configuration writes.
- Mainnet remains disabled by default; current autonomous execution is Testnet only.
- UI environment and freshness must come from runtime truth, never hardcoded labels.
- Build order is `pnpm build`, then `dotnet build`, tests, publish, and launch verification.
- The former Draft/Backtested/Shadow/Active/Degraded/Retired strategy registry lifecycle is retired from trading authority. Existing database tables may remain for non-destructive upgrade compatibility, but new runtime code must not read, write, rank, promote, or project them.
- Automatic trading no longer runs a strategy-candidate exploration/promotion ladder. Backtests and research may explore ideas offline, but live risk-increasing decisions are formed directly from current canonical candle structure and cannot be promoted by historical strategy scores.
- Legacy `Core.Strategies.MeanReversionStrategy` and optimizer code may remain available for offline/backtest compatibility, but it is not a live WPE Agent trading authority. The live Agent uses `DirectMarketStructureDecisionSkill`; no strategy-family score can bypass that direct context or Risk Gate.
- WebView host commands use an explicit allowlist. Currently only `open-settings` is accepted.
- `Modules/Trade/TradeView` and `Services/Execution/ExecutionService` are legacy Binance-direct code and are not mounted by the current Reference UI; do not reuse them for new trading flows.
- Legacy Remote Brain token/cost audit rows may still be readable for historical compatibility, but the trading runtime no longer creates remote Brain calls. New `BrainPlanner` trading skill calls are local-only and record no remote LLM usage/cost.
- `StructuredOutcomeMemory` remains a bounded local SQLite memory contract for the deterministic planner. It must preserve mode, risk, execution, recovery and state-change truth and cannot override current Market evidence or Risk Gate.
- `RecentOutcomesAsync` is retained only as a bounded local compatibility projection; new trading decisions do not compose remote prompts or depend on `BrainPromptComposer`.
- Monitoring may display historical LLM-governance/skill-call fields for compatibility, but new trading `BrainPlanner` calls are local-only with `remoteLlmUsed=false` and no remote token/cost authority.
- Model-off Macro research accepts observed facts only through `wpe.macro-facts/1.0` and a canonical `Macro` source. It validates source hash/status, UTC observation and release ordering, indicator identity, geography, frequency, unit, and numeric value; it does not infer forecasts, causal claims, or trading actions. This initially remained unpromoted pending official-source ingestion, revision handling, and independent acceptance; those bounded requirements were subsequently completed without certifying live target availability.
- The initial official Macro source is the keyless BLS public API v2 with an exact endpoint and allowlisted series. Since its observation payload omits formal publication time, ingestion records the fetch time with `releaseTimeBasis=official-endpoint-first-observed`; it must never present that value as the formal release timestamp. Raw responses are bounded and hashed, while malformed, unavailable, nonnumeric, unallowlisted, or transport-failed data produces no Macro observation.
- The production Agent now starts an independent Macro Research scheduler that reads the two allowlisted BLS series on startup and every six hours. Valid observations persist locally in an append-only revision chain keyed by indicator and observation month; identical values are idempotent, while a changed value appends the next revision and survives restart. Collection failure degrades only Macro health and never blocks the trading/recovery loop. Each seven-Agent production cycle reads the latest persisted revision per indicator into canonical Research facts with evidence hash and observation metadata; invalid, duplicate, future, or malformed persisted facts fail Research closed. Macro facts remain observation-only and cannot generate a forecast or trading action. Formal release-calendar evidence remains required before the standalone Macro capability is promoted.
- The Macro scheduler now reads only the pinned official BLS `bls.ics` release-calendar endpoint through a bounded read-only transport. It strictly unfolds and parses relevant CPI and Employment Situation events, converts explicit UTC or `America/New_York` timestamps to UTC, requires unique bounded event identities, hashes the raw calendar, and correlates each monthly observation only to one event in the immediately following calendar month that occurred before first observation. Formal time, event identity, and calendar hash persist append-only; stronger calendar provenance appends a new revision even when the numeric value is unchanged. Missing, denied, malformed, ambiguous, oversized, or unmatched calendars degrade Macro health and retain the honest `official-endpoint-first-observed` basis. `READY` requires both allowlisted series to have formal correlation. The current development network received an official BLS automated-access denial on 2026-07-27; the later bounded acceptance covers deterministic local behavior only, while live target-machine availability remains uncertified.
- Fundamental begins with a deliberately bounded venue-instrument contract, not narrative analysis. For Binance Futures Testnet, only the official public `exchangeInfo` response may establish that the exact target symbol is an active perpetual contract with coherent base, quote and margin assets and a valid onboard time. The raw symbol object and canonical fact are independently hashed, facts expire after 24 hours, Mainnet is rejected, and missing, duplicate, stale, future, malformed or tampered evidence blocks Research. These facts do not claim protocol health, tokenomics, issuer quality, valuation or an investment conclusion; this initially advanced from `no` to `partial`, before the later exact identity hardening enabled bounded acceptance.
- The seven-Agent model-off runtime now has a production orchestration boundary separate from fixture composition. It accepts exactly one fresh canonical Market, Research, Strategy, and Risk output for the same cycle, verifies canonical bytes/hash and each preceding handoff hash, then deterministically emits Execution, Recovery, Audit, and six ordered handoffs. Missing, duplicate, unexpected, stale, cross-cycle, tampered, ineligible, or Mainnet input fails closed and is still audited. This first production batch performs no external mutation; Execution and Recovery remain explicit zero-mutation outputs.
- The live trading cycle feeds an observation-only Model-off shadow after independent risk review and before order authorization. The deterministic composer maps current EvidencePack, direct decision review, independent risk and reconciliation truth into canonical audit inputs; the orchestrator persists all seven audit outputs. The shadow does not call a model, gateway, executor or exchange and cannot change the established direct local execution path.
- Automatic Testnet execution and reconciliation now append canonical Execution, Recovery, and Audit Agent observations from the existing `automatic_execution_queue` and append-only `automatic_execution_events`. Each state/sequence identity is immutable and repeated observation is idempotent; later states append new identities. Unknown/executing/reconciling outcomes are quarantined with `resubmit_allowed=false`. The observer has no gateway, executor, exchange, network, or model dependency, and observation failure cannot rewrite the persisted execution result.
- A queue-level `Succeeded` state is no longer sufficient for a successful Execution Agent observation. The observer correlates every durable intent against the same-cycle persisted `order_intents`: client ID, symbol, side, quantity, reduce-only semantics, terminal status, and presence of exchange order ID must agree. Opening intents require `PROTECTED`; reduce-only intents require `COMPLETED`. Missing, extra, malformed, unconfirmed, or conflicting rows quarantine Recovery with `resubmit_allowed=false`; identifiers and order IDs are not copied into canonical facts.
- Model-off remains shadow-only for trading authority. A blocked, partial, stale or persistence-failed seven-stage audit is recorded as audit truth but must not clear, approve or replace a direct local intent. Risk-increasing authorization is governed by the live direct decision, independent Risk review, reconciliation/capability gates and execution authorization; reduce-only recovery remains independently available.
- After automatic execution/reconciliation, the production gateway now performs a separate read-only exchange observation through `FindOrderAsync`; it has no place/cancel/update capability. Versioned evidence contains only sequence, structural state, exchange status, executed quantity, counts, UTC observation time, and a canonical SHA-256. The Execution observer independently validates the hash, freshness, execution identity, counts, exact durable-intent sequences/quantities, and `FILLED` status. Missing, conflicting, unknown, unsupported, stale, or tampered exchange evidence prevents a successful Execution observation and quarantines Recovery without resubmission.
- Automatic execution observation is restart-repairable. Before its processing loop, the worker pages append-only execution events by a persisted global event cursor (100 items per page, at most 10 pages per startup). The cursor advances only after a successful write or verified idempotent skip, so a state/event mismatch or observation failure cannot hide later work. A separate bounded, rotating cursor revisits only `Succeeded` executions that lack a Confirmed evidence identity; this permits append-only Unknown-to-Confirmed upgrades without rescanning completed history or starving records beyond the first page. Only `Succeeded` queue items trigger read-only exchange observation; blocked/nonterminal states never perform this network read.
- Teacher is accepted only as a bounded Research capability: once per UTC day it can format an eligible canonical Research output into a deterministic market brief, explain allowlisted macro indicators with fixed definitions, and enqueue it through the existing Telegram/WhatsApp outbox only when the user explicitly enables the `MarketBrief` event. It cannot ask questions, score users, infer forecasts, provide investment advice, submit orders, or publish from blocked Research. Delivery failure remains observational and cannot affect trading or recovery.
- Teacher voice is governed by the versioned `wpe.market-teacher-persona/1.0` contract: a 48-year-old senior market mentor who is evidence-first, calm, plain-spoken, experienced, and non-performative. The persona selects deterministic Chinese or English wording from the current WPE language and is included in the brief identity hash; it is not a model prompt and cannot alter facts, eligibility, notification consent, or trading authority.
- Teacher V2 is approved for design as a male financial professor approximately 68 years old with approximately 45 years of cross-market experience. It extends rather than silently changes the accepted V1 contract. V2 may use bounded public read-only network evidence, scheduled lessons, historical teaching and evidence-based research recommendations, but it has no order, strategy, risk, secret, provider-configuration or approval authority. Live equity recommendations remain unavailable until the corresponding current-data providers and evidence profiles pass acceptance.
- `MarketBrief` consent is configurable and persisted only through the secure WPF notification settings, with localized labels for every supported desktop language. The Web settings page may display the runtime event allowlist but remains read-only; it does not gain configuration or secret-write authority.
- The production planner consumes `StructuredOutcomeMemory[]` directly as local bounded context. The retired remote prompt-history projection is no longer part of trading; memory retains cycle/mode/exchange/symbol/risk/execution/state-change/recovery truth and never changes deterministic Local Only, Risk Gate, execution or recovery authority.
- Post-trade accounting is created only from a confirmed `FILLED` reduce-only execution. The close `client_order_id` is the durable identity: identical recovery replays remain idempotent even after later trades, conflicting close facts fail closed, and partial fills do not prematurely change realized PnL. Entry cost uses a deterministic decimal moving-weighted ledger across confirmed opens and prior reductions instead of the latest open price. The accepted outcome emits a bounded post-trade fact into local long-term memory. Fee provenance is governed by the later exchange-fee decision; broader causal strategy attribution remains outside this bounded component.
- Position truth has a model-free `wpe.position-reconciliation/1.0` gate. It derives the local net ledger from decimal execution facts, compares it with a fresh structurally valid provider position snapshot by canonical symbol/side, persists a canonical hashed report, and permits new risk only for an exact confirmed reconciliation. Stale, missing, duplicate, invalid, external-only, local-only, or quantity-conflicting legs fail closed, while the existing reduce-only recovery path remains available. Later protection, isolation, append-only and same-cycle invalidation work permits bounded Position acceptance without implying full Execution/Recovery acceptance.
- Post-trade review `wpe.post-trade-review/1.4` resolves strategy identity only from a unique persisted automatic execution artifact sharing the execution correlation ID. Manual and historical paths remain `legacy-version-only`; multiple strategy pairs for one correlation are marked `conflicting-correlation` with no strategy ID. This is identity attribution, not a causal performance claim.
- Exchange-reported fees are an optional read-only provider capability, separate from the mutation adapter contract. Binance Futures Testnet reads only `/fapi/v1/userTrades` for the exact order, validates unique fills, order/symbol identity, positive price and quantity, nonnegative commission, one commission asset, exact executed quantity, bounded response size, UTC freshness, and canonical SHA-256 before append-only persistence. Post-trade accounting uses observed fees only when the close and all contributing opens are confirmed in USDT; it never converts assets or treats missing evidence as zero. Collection failure cannot change execution truth. Mainnet and other providers remain unsupported for this capability.
- Post-trade review 1.3 treats slippage as provider-neutral execution-quality attribution, not an additional PnL charge. The execution ledger persists each intent expected price beside the confirmed fill average. For longs, paying above expectation to open or selling below expectation to close is adverse; shorts use the inverse direction. Remaining entry slippage is reduced proportionally with prior reductions. Positive values are adverse and negative values favorable. Missing historical expectations produce `unavailable` and zero explanatory fields rather than invented observations; changing only the expected price on a completed-close replay is an identity conflict.
- Post-trade review 1.4 adds signed exchange funding without treating a missing response as zero. Binance Futures Testnet reads only `/fapi/v1/income` with `incomeType=FUNDING_FEE`, splits history into bounded seven-day windows, and emits `Available` only when every chunk succeeds. Canonical funding events and complete observation windows persist append-only. Funding changes net PnL exactly once only for a full close of one unambiguous position epoch, with exchange timestamps, no prior reduction or opposite-side overlap, complete fresh window coverage, and USDT-only events. A successful empty window is confirmed zero; all other unsupported, stale, malformed, partial, ambiguous, legacy, or errored cases remain zero with basis `unavailable`. Collection stays observational and cannot alter execution truth.
- `review-post-trade` is accepted as a bounded component after review schema 1.4: confirmed-close identity, moving-weighted entry accounting, fee provenance, funding provenance, provider-neutral slippage, bounded strategy identity, replay conflict detection, and long-term review memory are deterministic and model-free. This acceptance does not upgrade the Audit aggregate, certify other providers' fee/funding evidence, or claim broad causal-performance attribution.
- Position protection now has an independent read-only `wpe.protection-reconciliation/1.0` gate. Each provider position must have deterministic stop-loss and take-profit evidence through a combined `OCO`/`POSITION_TPSL`, explicit stop/take orders, or two generic trigger/TPSL legs. Missing legs, orphan protection, invalid direction, stale observation, or canonical tampering blocks new risk without invoking a mutation. Binance, OKX, Bitget, and Gate expose protection evidence through their open-order adapters. Bybit additionally reads position-level `stopLoss`/`takeProfit` state from `/v5/position/list` and projects it as synthetic read-only protection evidence; those synthetic identities are explicitly rejected by the ordinary cancellation endpoint. Reduce-only recovery remains available.
- External exchange positions now have a separate model-free `wpe.external-position-isolation/1.0` fact. It records only the positive quantity by which a fresh exchange leg exceeds the local execution ledger, persists canonical tamper-evident evidence, and blocks new risk while isolated, stale, or invalid. It never adopts, closes, protects, or otherwise mutates an external position; local-only or undersized exchange conflicts remain owned by Position reconciliation, and reduce-only recovery remains available.
- Production planning performs one bounded local SQLite retrieval across working, episodic, and long-term memory. Retrieval is scoped to the active or highest-priority fresh symbol, permits symbol-neutral facts, takes at most two newest facts per tier, and bounds every summary to 100 characters. The local deterministic planner consumes this evidence without any remote model call. Memory remains advisory and cannot override current Market evidence, Risk, authorization, reconciliation, or recovery gates.
- Signed historical collection cursors require canonical Base64 for both payload and signature before HMAC validation. Alternate textual encodings that decode to the same bytes are rejected, making cursor tampering fail closed deterministically alongside expiry and collection binding.
- Brain call observability now persists compact safe metrics with each runtime skill call: context characters, input/output tokens, cache hit, governed outcome, token source, latency, total billable tokens, and cost. Cache hits and blocked calls retain zero billable token/cost semantics while still exposing context size and outcome. Raw prompts and responses remain excluded from the runtime projection and are redacted in legacy skill audit storage.
- The live Market Agent treats account, positions, and each market as separate deterministic evidence. Account truth must be fresh UTC data with positive equity and internally valid balances; positions must have valid symbols, positive quantities/prices/leverage, and no duplicate symbol/side leg. Each market receives its own source status, while any invalid required source blocks downstream eligibility. This remains a local composition rule and adds no network, model, or mutation dependency.
- Model-off Research is a shadow audit stage, not a live trading prerequisite. It must remain bound to the current instrument and canonical evidence, but historical backtest scores, `Approved/Promoted` flags, or research validation records cannot create or increase trading authority. Malformed audit inputs fail that audit stage closed without changing the direct local execution decision.
- Model-off Strategy is a shadow audit projection of the already-formed direct local decision. It may verify current-instrument identity, freshness and executable price geometry for audit eligibility, but it cannot publish a competing risk-increasing plan. Live order authority remains direct local decision + deterministic plan + independent risk + reconciliation/execution gates.
- The live Risk Agent treats `Approved` as one field in a coherent deterministic review, not as authority by itself. Risk increase requires positive planned quantity, risk amount, and post-trade exposure; approved reviews cannot contain blocking reasons or a blocked level. The bounded unique check-name set is hashed into canonical facts, while summaries and free-text failures remain excluded.
- Automatic Execution and Recovery observations require a contiguous event sequence starting at one, exact previous-to-next state linkage, nondecreasing UTC timestamps no later than evaluation, and a terminal state matching persisted queue truth. The Audit Agent's success means the outcome was faithfully recorded, not that the trade succeeded: valid rejected, failed, and unresolved outcomes use `record_execution_exception` with `execution_succeeded=false`. A malformed timeline blocks all three observation roles.
- The canonical seven-Agent Risk input now requires the current cycle's tamper-evident Position reconciliation, protection reconciliation, and external-position isolation reports. It independently validates each canonical identity and relative freshness, records their hashes as bounded sources, and blocks risk increase when any report is missing, replayed, malformed, conflicting, incomplete, stale, or isolated. The existing reduce-only recovery path remains separate and available. This closes the prior evidence gap between the position safety gates and the seven-Agent handoff, but does not by itself promote the full Position capability or constitute live Testnet evidence.
- The bounded Position component is accepted only for deterministic quantity reconciliation, explicit stop/take protection evidence, external-position isolation, append-only local audit, and invalidation of current-cycle authority after any successful recovery mutation. Duplicate unclassified `TRIGGER`/`TPSL` orders no longer prove both protection legs; Gate and Bitget emit explicit stop/take types only from provider facts or owned client identities. This acceptance does not upgrade Execution/Recovery aggregates or claim live Testnet provider certification.
- The bounded Orchestrator/control component is accepted for the deterministic seven-stage canonical audit chain. A production cycle persists all seven canonical outputs and six ordered handoffs in one SQLite transaction; exact replay is idempotent, any output or handoff identity conflict rolls the whole audit attempt back, and both evidence tables reject update/delete at database level. This audit integrity does not grant pre-authorization or mutation authority and does not upgrade any aggregate to live Testnet execution evidence.
- Realtime market enrichment is evidence-gated rather than message-gated. Unknown events and malformed known events cannot refresh symbol freshness or message counts; hub health requires a fresh positive price plus coherent bid/ask evidence for every subscribed symbol; and REST market evidence is enriched only by a connected, fresh, complete realtime snapshot. This hardens Market input truth but does not yet accept the full Market Data capability.
- REST market composition now uses only structurally valid, uniquely timed, fully closed UTC candles. Binance and the shared OKX/Bybit/Bitget/Gate path derive price, support/resistance, RSI, trends, volatility and `CollectedAt` from the same confirmed candle set; request completion time can no longer relabel stale or still-open data as fresh. Raw provider-response retention remains outside the bounded acceptance scope.
- Market evidence now carries `wpe.market-evidence-provenance/1.0`: provider, Testnet environment, symbol, source time, confirmed-candle bounds, canonical bytes and SHA-256. Evidence collection binds the final REST/realtime-enriched fact, and the Market Agent independently recomputes it; missing, altered, cross-symbol or Mainnet provenance fails closed. Together with confirmed-candle and realtime completeness gates this permits bounded Market Data acceptance, without claiming raw HTTP retention, live provider certification, or full Market Agent acceptance.
- Technical decision evidence is now direct local candle-structure evidence. Risk-increasing decisions require untampered canonical Market provenance, coherent current-instrument 15m/1h/4h candles, bounded market quality and an exact direct-decision context identity. The retired runtime signal-aggregation score is not an execution input.
- Live News evidence is now a bounded canonical input to the seven-Agent Research output. Every supplied item must match an allowlisted publisher and HTTPS host, use valid UTC/fresh timestamps, a canonical duplicate identity, bounded asset/event/reliability fields, and finite confidence/sentiment values. Research records only per-item canonical hashes plus aggregate counts/hashes; article bodies and titles are not copied into the Agent audit. Malformed, duplicate, spoofed, or wholly unavailable News evidence fails Research closed, while a valid cycle with no target-specific headline remains neutral rather than inventing a signal. This is production evidence-chain hardening, not a claim that News source availability has completed live acceptance.
- The bounded `news` component is accepted for canonical evidence admission only: allowlisted publisher/HTTPS-host binding, UTC freshness, duplicate rejection, bounded structured fields, hashed title identity, and exclusion of article text from Agent audit. Acceptance does not certify live feed availability, independent article truth, causal market interpretation, or the Research aggregate.
- The Model-off `strategy` component is an audit-stage projection only. It may summarize a deterministic current-instrument direct decision and coherent entry/stop/take geometry, but it has no lifecycle/promotion authority and cannot authorize or modify an order. The live order path does not require an Active/Shadow strategy registry record.
- The bounded `macro` component is accepted for observation-only ingestion of the two allowlisted official BLS series. Official API and calendar endpoints are pinned; future, out-of-window, duplicate, malformed, or nonnumeric observations fail closed; raw evidence is hashed; numeric and stronger calendar-provenance revisions append; failed refresh degrades health without deleting the last valid fact. This acceptance does not create forecasts, causal trading conclusions, broader macro coverage, target-machine network certification, or Research aggregate acceptance.
- The bounded `fundamental` component is accepted only as Binance Futures Testnet venue-instrument truth from official `exchangeInfo`. Provider, environment, canonical/native symbol, base/quote/margin assets, active perpetual status, onboard time, freshness, raw-symbol hash, and canonical hash must agree exactly; aliases, case changes, cross-symbol mappings, Mainnet, other providers, stale facts, and tampering fail closed. This is not protocol, issuer, tokenomics, on-chain, valuation, investment analysis, or Research aggregate acceptance.
- The Model-off Research audit must expose component evidence as canonical sources rather than facts-only decoration. Valid Macro/News evidence contributes bounded source hashes, while the current-instrument direct candle-structure context is bound to the exact canonical Market provenance. Missing, conflicting, noncanonical or cross-identity evidence blocks downstream Model-off audit eligibility, but it does not substitute a research score or strategy promotion gate into live trading authority.
- The retired strategy-score research path (`ResearchValidationResult` and strategy promotion gates) is no longer part of trading authority. Live risk-increasing decisions come from fresh canonical Market evidence plus direct local candle-structure context, then pass deterministic planning, independent risk, reconciliation and execution gates. Backtests and research artifacts remain observational/validation evidence and cannot authorize an order.
- The future portable Windows package must keep executable files immutable and separate from `%LOCALAPPDATA%\WPE Agent` state. Upgrades replace or switch application directories, never bundle secrets/databases, and retain an independently verified last-known-good directory for rollback.
- Repository truth and delivery boundaries are now treated as product safety surfaces. The README must identify WPE Agent, its current project version, Local Only behavior, Testnet/Paper default, Mainnet prohibition, bounded capability status, and the authoritative context files. CI must target the explicit solution/test/main-project paths and reject runtime state, credentials, databases, private keys, and certificates from publish output. Historical project filenames and excluded legacy modules remain quarantined in place until the seven-Agent backend is complete; they must not be renamed, reorganized, or reused piecemeal during active safety work.
- Technical Research facts must bind one uppercase canonical symbol to an explicit `marketSymbol`, the exact `market:{symbol}` source identity, and the matching canonical Market evidence hash. A hash match alone cannot authorize cross-symbol technical evidence.
