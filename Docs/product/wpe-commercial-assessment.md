# WPE 商业化产品评估

## 结论
WPE 不是普通交易机器人，也还不是成熟量化平台；它最接近“带风控与审计的本地化交易 Agent 平台原型”。当前竞争力来自闭环、风控、审计和多层 UI/Agent 编排，但产品化短板仍在数据历史、策略市场化、协作治理和统一主闭环。

## 目标用户
- 个人量化交易者，尤其是想把策略、回测、风控、执行放在一个桌面端里的人。
- 小型量化团队，需要本地可控、可审计、可测试的交易工作台。
- 进阶 AI 交易实验者，希望把 LLM 作为研究/决策协作层，而不是直接下单层。

## 核心问题
- 交易流程割裂：数据、回测、实盘、风控、复盘分散在不同工具里。
- 自动化不可信：很多机器人只有信号，没有完整风险门禁和审计链路。
- 策略难管理：缺少策略生命周期、筛选、降级、恢复和复盘能力。
- LLM 不可控：AI 可以辅助，但不能越权直连交易所。

## 现有功能地图
- 数据与行情：实时行情、资金费率、历史/缓存数据、数据质量规则。
- 策略研究：回测、Walk-Forward、网格优化、策略模板、机器学习/特征工程。
- 风控：Risk Gate、仓位管理、杠杆控制、黑名单、最大回撤等规则。
- 执行：实盘/模拟/测试网、订单查询、订单执行、交易所适配器。
- Agent：策略研究调度、脑力决策、证据收集、技能守卫、新闻研究、记忆存储。
- UI：仪表盘、风险、回测、监控、告警、账户、市场、策略设置。
- 审计与存储：SQLite 持久化、交易记录、运行状态、测试/恢复用存储。

## 主要缺口
- 历史订单、权益曲线、回测结果、技能调用、审计事件还没形成统一采集协议。
- 旧 Binance 直连执行链已删除，当前权威链统一为 `AutoTradingAgent` / `ReliableOrderExecutor` / provider。
- 主闭环对团队协作、权限、审批、工作流支持不足。
- LLM 侧还缺少统一记忆层、成本/延迟/上下文治理的产品化面板。
- 多交易所、多账户、多环境的统一运营视图还不完整。

## 3 个差异化护城河
1. 闭环护城河：研究、风控、执行、审计、恢复在同一系统内闭环，不只是发信号。
2. 可信护城河：Testnet 默认、Risk Gate 强制、技能白名单、SQLite 审计，适合做“可控 Agent”。
3. 本地控制护城河：WPF 主控 + Web UI 投影 + 本地数据/秘钥治理，适合高敏交易场景。

## 分层方案
### MVP
- 单交易所
- Testnet / Paper / 回测闭环
- 基础风控、告警、审计、策略模板
- 只读 Web UI 与桌面主控

### Pro
- 多策略生命周期管理
- Walk-Forward、优化、策略评分
- 更完整的历史数据与复盘报表
- 统一 Agent 研究面板与记忆层

### 团队版
- 多账户/多角色权限
- 策略审批流与发布流
- 统一审计、合规模板、操作留痕
- 多交易所适配与团队级监控

## 90 天路线图
### 0-30 天 Backlog
- 第 1 周：动态市场目录
  - 验收：市场目录可按交易所/品种/状态动态刷新，UI 与运行时同源。
- 第 2 周：多品种配置
  - 验收：策略、风控、执行支持多品种配置下发与持久化。
- 第 3 周：`RuntimeSnapshotV1`
  - 验收：统一输出运行态快照，覆盖账户、持仓、订单、风控、市场摘要。
- 第 4 周：真实订单/持仓 UI + 第二交易所只读适配器
  - 验收：UI 可展示真实订单与持仓；第二交易所仅只读接入，不可执行。
- 31-60 天：完善策略生命周期、策略市场、复盘报表和 LLM 治理面板。
- 61-90 天：上线团队协作能力、权限审批、统一监控和多交易所运营视图。

## 关键指标
- Testnet->Paper->Live 的闭环成功率
- 风控拦截率与误拦截率
- 策略入选率、存活率、回撤控制
- 下单成功率、恢复成功率、重复下单率
- 日志/审计覆盖率、回测复现率
- LLM 调用成本、延迟、越权拦截率

## 明确不做什么
- 不做“无风控的全自动开单机器人”。
- 不让 Web UI 直接持有密钥或直连交易所。
- 不把 LLM 设为最终下单权威。
- 不在主产品里继续扩展旧 Binance 直连链路。
- 不先做高频交易或超低延迟撮合竞争。
