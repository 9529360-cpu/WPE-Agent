# WPE 产品闭环审计（2026-07-28）

## 当前产品定位

WPE 当前是本地优先、私人使用、Binance Futures Testnet、七 Agent 全自动闭环的交易研究与执行终端。Local Only 必须可运行；模型只能增强研究，不能替代确定性风控、执行、恢复和审计。Mainnet、股票实盘和商业客户分发均不在当前已验收范围。

## 已确认真实接通

- 七 Agent 运行状态、当前会话交接、策略注册/生命周期/回测。
- Testnet 行情、账户、持仓、订单、风险、执行、恢复和审计投影。
- Teacher V2 的受限加密课程、研究候选、更正、结果评估和独立通知许可。
- Telegram 单目标加密配置、测试发送、outbox、重试和运行时统计。

## P0 闭环修复

- [x] 当前会话交接只显示新鲜租约且 RunId 一致的数据，禁止历史日期冒充当前交接。
- [x] Web runtime 接入真实 `automaticExecutions`，交易页显示执行状态、原因码、次数和更新时间。
- [x] 当前私人全自动产品不再把旧待审核队列作为主交易流程。
- [x] Telegram 配置按钮使用独立宿主命令并直达 WPF 通知页；Token 永不进入 Web UI。
- [x] readiness 通过后自动启动七 Agent；未知、陈旧或权限不完整仍 fail-closed，并保留手动重试。
- [x] Telegram `/start` 订阅登记、范围授权、逐订阅者幂等 outbox、停用和审计通过本地确定性端到端验收。
- [x] Telegram 订阅者状态以脱敏只读投影进入 runtime；批准和停用动作留在本机 WPF 安全边界。

## P1 产品增强

- [ ] 用后台异步快照循环替换 UI 线程每两秒同步查询多个 SQLite 投影。
- [ ] 统一中文与其他语言的组件树；语言切换只换字典，不再切换两套产品。
- [ ] 增加策略可解释时间线：市场状态 -> 候选 -> 回测 -> Shadow -> Active -> Risk Gate -> 执行/拒绝 -> 复盘。
- [ ] Telegram 展示轮询/分发健康、退避、积压和死信；`getUpdates` 明确只允许本机单实例消费。
- [ ] 将历史净值、回测、技能调用和审计分页接入当前研究/监控页面。

## 当前禁止误导

- Mainnet 按钮必须显示未开放，不得表现为当前可切换能力。
- Teacher 当前只声明已验收的加密范围；股票、广泛跨资产、官方新闻和宏观因果仍是后续范围。
- `ProfessionalDistribution` 是未来商业合规模块，不进入当前私人版主导航，也不复用为 Telegram 订阅注册表。
- UI 不得展示静态订阅人数、演示 Agent、虚构订单、虚构策略或由前端推断的执行结果。

## 验收顺序

1. Telegram intake、加密身份、订阅投递和通知直达入口。
2. 自动执行投影、当前会话交接和自动启动。
3. 前端 typecheck/build 与通知、运行时、宿主桥定向测试。
4. 全量 Release readiness、发布候选、启动验证和仓库同步。
